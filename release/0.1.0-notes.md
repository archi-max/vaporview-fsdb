# VaporView FSDB 0.1.0 (pre-release)

VaporView FSDB is a fork of [VaporView](https://github.com/Lramseyer/vaporview) (GPL-3.0) by Lloyd Ramseyer and
contributors that opens FSDB waveform dumps in VS Code; it is not affiliated with or endorsed by upstream VaporView.
Its bundled reader, wisp-helper, decodes FSDB and WCZ itself; no vendor software is needed. VCD, FST and GHW open too.
Large dumps load in windows, so you can open them over Remote-SSH where they were simulated. If you only need
VCD/FST/GHW viewing, upstream VaporView is the original. **Pre-release:** install from the VSIX files below.

## Features
- **FSDB and WCZ, read natively:** the bundled wisp-helper reads them itself (no vendor software); large signals load in windows; works over Remote-SSH. Tracing needs your design (slang profile or `vaporview.trace.designArgs`); the editor link needs slang-server.
- **Debug mode** ("Debug This Waveform", F5): step cycles forward and back, play, breakpoints (change, value, text, SystemVerilog condition, source line), watches, Evaluate, Locals, and editor marks.
- **Trace Driver at Marker:** the statement, branch and inputs that set a value, with step back and forward.
- **Trace to Root (Trace-X):** follows drivers back to where a value (such as an X) came from; exact/approximate steps, ranked causes.
- **Editor link and inline values:** signal ↔ SystemVerilog source, values at the marker after each line, enum names (needs slang-server).
- **No value is not x:** a signal has a real value, a value "via …" the design, or "no value" with the reason; "no value" is never drawn or evaluated as x.
- Everything from VaporView also works: VCD/FST/GHW, markers, value formats, search, sessions.

## Which file

| File | For | Contains |
|---|---|---|
| `vaporview-fsdb-0.1.0-linux-x64.vsix` | Linux x86-64, locally or as the Remote-SSH host | wisp-helper for FSDB / WCZ (glibc 2.17+), prebuilt slang design model |
| `vaporview-fsdb-0.1.0-universal.vsix` | macOS, Windows | macOS: wisp-helper for FSDB / WCZ (arm64 + x86-64, macOS 13.3+) and the prebuilt design model (macOS 11+). Windows: FSDB / WCZ through Remote-SSH / WSL; driver tracing not supported yet |
| `SHA256SUMS.txt` | checksums | |

Install with `code --install-extension vaporview-fsdb-0.1.0-<platform>.vsix`. In a Remote-SSH window, run it in the
remote terminal so it installs on the Linux host. The native programs need only the C library (glibc 2.17 or newer;
no libstdc++, no zlib). This release has no linux-arm64 VSIX.

If you installed an earlier vaporview-wisp development build, uninstall it first
(`unpublished-tbd.vaporview-wisp`, or `unpublished-tbd.wisp` for an earlier test build).

## New settings

Settings and command ids use the `vaporview.*` prefix (`wisp` in a setting name means the bundled reader).

| Setting | Default | What it does |
|---|---|---|
| `vaporview.wispHelperPath` | empty | Path to wisp-helper. Empty: the one packaged with the extension |
| `vaporview.wisp.windowing` | on | Load FSDB / WCZ signals in windows; off loads every signal whole |
| `vaporview.wisp.remoteMode` | auto | Windowed loading tuned for a remote link; auto = on when the extension runs remotely |
| `vaporview.wisp.outsideWrites` | unknown | FSDB: whether the simulation wrote design signals from outside the logic. `none` lets port copies without stored values be computed. Can be set per folder |
| `vaporview.wisp.portLinks` | on | FSDB: link port copies to their drivers. Can be set per folder |
| `vaporview.wisp.forceLog` | empty | FSDB: the simulator's force log, so forced port copies are detected |
| `vaporview.wisp.directOpen` | lazy | FSDB open mode |
| `vaporview.wisp.verifyStart` / `checkThreads` | idle:30 / 2 | When and how wide the background whole-file check of a lazily opened FSDB runs |
| `vaporview.wisp.planBudgetMB` | auto | Memory budget for the FSDB reader (read plan and computed signals); auto = 40% of RAM, with computed signals at most 8 GB |
| `vaporview.wisp.workers` / `cacheMb` / `env` | helper defaults | wisp-helper threads, decoded-block cache, extra environment |
| `vaporview.trace.designArgs` / `designRoot` | empty | slang arguments of the design (else the editor link's design / slang profile) and their base folder; relative to designRoot, else the folder whose settings set them |
| `vaporview.trace.prepare` | onOpen | When the design model loads |
| `vaporview.trace.xprop` | auto | X-propagation when re-executing a statement |
| `vaporview.trace.xChainSteps` | 30 | Trace to Root step budget |
| `vaporview.trace.driverHighlight` | on | Mark the lines that assign the selected signal and highlight the one driving it at the marker |
| `vaporview.trace.verdiHome` | empty | Path to your Verdi installation, for the optional cross-check |
| `vaporview.sourceLink.slangConnection` / `slangServerPath` | auto / empty | How the editor link reaches slang-server |
| `vaporview.sourceLink.autoPickProfile` / `elaborate` | on / ask | Build the design from a slang profile; offer to elaborate when slang-server has no top level |
| `vaporview.sourceLink.pathMapping` | empty | "design prefix = waveform prefix" rules (inferred rules are added) |
| `vaporview.debug.inlineValues` | stoppedLine | Debug mode: values as quiet text after the stopped line; `all` for every line, `off` for none |
| `vaporview.sourceLink.inlineValues` | cursorLine | Values at the marker as quiet text after the cursor line; `all` for every visible line, `off` for none |
| `vaporview.sourceLink.enumNames` | on | Enum member names on waveform rows |

## Upstream VaporView
VaporView FSDB keeps VaporView's `vaporview.*` command and setting ids and its waveform editor, so only one of the two
can be enabled. With both enabled, VaporView FSDB shows a warning with a button for each and stays inactive. Disable
one and reload the window.

## Known issues
- **Some port copies show "no value" under the default `outsideWrites` (unknown).** Port copies that the FSDB does not
  store show "no value (port copy: values not linked yet)", and some deep port copies in large designs (for example
  CVA6 resets) still show "no value (not computable: …)" although they could be resolved. They are listed greyed in
  the netlist with the reason, but can't be added as waveform rows yet. Setting `vaporview.wisp.outsideWrites` to
  `none` for a folder whose simulation wrote nothing from outside the logic (as the other demo folders do) makes the
  reader compute them. The large CVA6 demo folder leaves `outsideWrites` unknown on purpose, as users get by
  default. Improved in 0.1.1.
- **Very large FSDB files under `outsideWrites` none:** some computed signals may show "no value (computed signals
  need more memory than vaporview.wisp.planBudgetMB allows)". The reader needs about 2 bytes of memory per byte of
  dump for them; raise the setting if you have the RAM. Under the default planBudgetMB (auto), the memory for computed
  signals is at most 8 GB, so on very large dumps they show this "no value" at once; set a number to allow more. The
  first read of such a signal then builds it for the whole file, which can take tens of seconds.
- **The first Locals list can be slow under `outsideWrites` none.** In debug mode the stopped line's values appear at
  once. With `vaporview.wisp.outsideWrites` set to `none`, the first Locals list of a large instance in a large FSDB
  waits while the reader prepares computed signals (about 10 s for a 155-signal CVA6 instance, longer on larger dumps
  or a busy machine); with the default it takes about a second. The status bar says what it is reading, and later
  reads are fast. VS Code does not ask for Locals while the Run and Debug side bar is closed. Improved in 0.1.1.
- **An inline or editor-link value of a computed signal can occasionally show "no value"** although the signal has
  one; the status bar counts it as a signal that can't be read. Waveform rows are not affected. Fixed in 0.1.1.
- **Trace says "not a signal of the design" for some names:** an element of a multi-dimensional array
  (`tag_mirror[3][1]`), a signal read through an interface modport (`master[6].Slave.w_data`), and an input that a
  generate block reads from its enclosing module. Trace the whole array or the interface instance's signal instead.
  Fixed in 0.1.1.
- **Trace Driver stops at a `for` loop inside a procedure:** it names the whole loop as the driving statement
  (approximate, "not re-executed"), without the assignment inside it, its branch or its inputs. The driver highlight
  marks the whole loop as the driving statement. Fixed in 0.1.1.
- Windows: no local FSDB / WCZ (use Remote-SSH or WSL), and driver tracing is not supported yet (the extension says
  so). The macOS helper needs macOS 13.3+.
- The publisher id is a placeholder. Marketplace / Open VSX publishing is a later decision.
